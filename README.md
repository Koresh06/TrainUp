# TrainUp

Telegram-бот для записи на тренировки, оформления заявок на программы тренировок
и консультации с тренером. MVP разрабатывается под одного тренера, архитектура
сразу закладывает возможность подключения других тренеров в будущем (по подписке).

## Статус

🚧 MVP готов, добавлен второй этап: клиенты без Telegram, новое расписание,
сводки тренеру, абонементы и оплаты, подтверждение явки, оценки, отпуск,
дневник прогресса, реферальная программа.

**Клиент** (вход по инвайт-ссылке тренера `/start <token>`, по ссылке друга
`/start ref_<code>` или по персональной ссылке из карточки `/start cl_<token>`):
- Регистрация с настраиваемой анкетой тренера (здоровье, цели, свои вопросы)
- 📅 Запись на занятие: календарь → время → подтверждение (лимит активных записей,
  прошедшие слоты скрыты), уведомление тренеру с анкетой клиента
- 📋 Мои записи — ближайшие тренировки и их статус (отмена/перенос — через тренера
  или кнопкой в напоминании)
- 🏋 Программа тренировок, 💬 Консультация — заявки тренеру
- ✉️ Обратная связь: обратный звонок, сообщение тренеру, ❓ FAQ
- 📝 Моя анкета — просмотр и обновление ответов, остаток абонемента
- 📈 Мой прогресс — вес и обхваты, фото «до/после», графики
- 🎁 Пригласить друга — личная ссылка и пошаговое объяснение программы (см. ниже)
- Накануне — «Завтра в 18:00 — придёте? ✅ Приду / ❌ Не смогу», перед тренировкой
  напоминание, после — «Как прошла тренировка?» 1–5 ⭐; напоминание «запланируйте
  следующую тренировку» через 3 дня после занятия

**Тренер** (`/trainer`): онбординг (рабочая группа выбирается системной кнопкой
Telegram) и подписка, постоянные клиенты с еженедельным автосозданием,
📨 заявки клиентов со статусами (и кнопками прямо в рабочей группе),
статистика с графиками (тренировки, неявки, оценки, доход, загрузка по дням и
часам), профиль, 💎 подписка; настройки — расписание (шаблоны + вместимость),
🚫 блокировка дней/слотов и 🏖 отпуск, цены, правила записи, вопросы анкеты,
напоминания и сводки; ❓ помощь — FAQ с правилами пользования ботом.

- **📅 Расписание** (бывшие «Бронирования») — сразу день: лента «время · статус ·
  клиент» с бейджами 🔁 постоянный, 📵 без Telegram, 👍 подтвердил явку, итог
  «N тренировок · ≈ сумма»; ◀️/▶️ по дням, «Сегодня», 📆 выбор даты (дни с
  тренировками подсвечены), 🗓 неделя по дням, ⏳ ждут подтверждения (подтвердить
  прямо из кабинета), 🕓 история по месяцам с фильтрами «проведены / отмены /
  неявки» и итогами, ➕ записать клиента на выбранный день. Карточка записи:
  контакты и заметка, цена и оплата, кто и когда отменил, оценка клиента;
  подтвердить / перенести / отменить (с подтверждением) / «🚫 Не пришёл» /
  «↩️ Всё же пришёл» / «💵 Отметить оплату» / к карточке клиента. В меню — бейдж
  «сегодня N · ⏳M».
- **👥 Мои клиенты** — 🔁/📵 в списке; карточка: контакты, заметка тренера,
  постоянные времена, ближайшие записи, проведено/отмен/последний визит,
  абонементы и долги, кто пригласил и скольких привёл, анкета. Действия:
  📅 записать на тренировку (сразу подтверждено, лимит клиента не действует,
  вместимость — да), 📣 позвать на тренировку, 📈 прогресс, 🎫 абонементы,
  💵 оплаты, ✏️ изменить. Разделы «😴 Давно не были» и «💵 Должники».
- **Клиент без Telegram** — тренер заводит карточку сам (только имя обязательно),
  ведёт расписание, абонементы и прогресс. Бот такому клиенту ничего не пишет
  (уведомления, напоминания и рассылки пропускаются). «🔗 Пригласить в бота» —
  одноразовая персональная ссылка: человек подтверждает «это я», карточка
  становится его аккаунтом со всей историей.
- **☀️ Сводка в личку** — утром (по умолчанию 8:00) «Сегодня у вас N тренировок»:
  время, клиенты, заметки, неподтверждённые, ожидаемый доход, кнопка
  «📅 Открыть расписание»; по желанию вечером «Завтра у вас…»; в дни без
  тренировок — только если включено.
- **🎫 Абонементы и оплаты** — абонемент на N занятий (цена, срок, оплачен сейчас
  или позже). Проведённая тренировка списывает занятие сама (неявка — тоже, если
  тренер не выключил), клиенту приходит «осталось 1 занятие» / «абонемент
  закончился», тренеру — что пора продлевать. Разовые тренировки отмечаются
  оплаченными в карточке записи или клиента; долги — «💵 Должники».
- **👤 Профиль** — всё, что видит клиент, правится здесь: имя, «о себе», телефон,
  фото, соцсети; группа уведомлений (название + проверка, что бот туда пишет;
  смена группы — только после успешного проверочного сообщения);
  «👁 Как меня видят клиенты»; подписка, клиенты, тренировки и ⭐ за 30 дней.
- **🏖 Отпуск / больничный** — период целиком: предпросмотр (сколько слотов
  закроется, чьи записи отменятся, кого предупредить лично), закрытие слотов,
  отмена записей с сообщением клиентам; слоты, которые календарь создаст позже
  внутри периода, сразу закрыты, постоянные тренировки не создаются.

**Реферальные программы — две отдельные:**

| | клиент → друг | тренер → тренер |
|---|---|---|
| где | «🎁 Пригласить друга» в меню клиента | «🎁 Пригласить тренера» в кабинете |
| ссылка | `/start ref_<code>` | `/start tr_<code>` |
| приглашённому | запись к тому же тренеру | пробный период длиннее на `TRAINER_REFERRAL_FRIEND_DAYS` (7) дней |
| пригласившему | N бесплатных занятий (бонусный абонемент на 90 дней), когда друг **сходил на первую тренировку** | +`TRAINER_REFERRAL_BONUS_DAYS` (30) дней подписки, когда коллега **впервые оплатил** подписку (в боте или наличными через админа) |
| кто задаёт бонус | тренер: ⚙️ Настройки → 📅 Запись (0/1/2, по умолчанию выкл.) | `.env` |

Бонус — один раз за каждого приглашённого, число приглашений не ограничено.
На обоих экранах пользователю расписано «как это работает» и видно, кого он
пригласил и за кого бонус уже начислен.

**Подписка тренера.** Новый тренер сразу после регистрации получает бесплатный
пробный период (`APP_CONFIG__BUSINESS__TRAINER_TRIAL_DAYS`, по умолчанию 7 дней,
0 — выключить); оплата во время триала начинается после его окончания.
Предупреждения за 48 и 3 часа до окончания (настраивается
в `.env`, для триала — свои тексты), по окончании — кабинет тренера и запись его клиентов закрываются,
в сообщении кнопка «💳 Продлить подписку» → выбор тарифа. Продление добавляет
срок к текущей подписке.

**Оплата подписки** (цены тарифов — в USD). Способы оплаты — стратегии
`PaymentProvider` в реестре `PaymentProviderRegistry`; тренер видит только
включённые в `.env`:
- 💳 **ЮKassa** — сумма пересчитывается в RUB по `USD_TO_RUB_RATE`; подтверждение
  только webhook'ом (`webhook`-сервис, FastAPI), статус перепроверяется в API ЮKassa;
- ⭐ **Telegram Stars** — инвойс в XTR по `USD_PER_STAR`, подтверждает `successful_payment`;
- 🤝 **Через администратора** — админам приходит заявка с кнопками
  «✅ Оплата получена / ❌ Отклонить», подтверждение сразу активирует подписку;
- 🧪 тестовая оплата — только при `APP_CONFIG__PAYMENT__TEST_MODE=True` (разработка).

Новый способ оплаты = новый класс в `src/infrastructure/payment/providers/` +
одна строка регистрации в `providers/services.py`; use case'ы, диалог оплаты и
подтверждение не меняются. Подтверждение идемпотентно (`SELECT … FOR UPDATE`):
повтор webhook'а или двойное нажатие не выдаст подписку дважды.

**Админ** (`/admin`, `ADMIN_IDS` из конфига):
- 📊 статистика за сегодня/неделю/месяц/всё время: тренеры, клиенты, тренировки,
  заявки, оплаты (в боте / наличными), бесплатные периоды, топ тренеров;
- 👥 пользователи: все, кто писал боту (тренеры / клиенты / без регистрации),
  новые, активные (DAU / WAU / MAU, «уснувшие» 30+ дней), заблокировавшие бота
  (по `my_chat_member`), конверсия «пробный период → оплата»;
- 📈 графики (PNG, matplotlib): новые пользователи, активность и блокировки,
  выручка, занятия всех тренеров;
- 👨‍🏫 тренеры: карточка-отчёт, выдача подписки (оплата наличными по тарифу или
  бесплатный период на N дней), блокировка, рассылка его клиентам;
- 👥 клиенты: поиск по имени/телефону/@username/ID, блокировка;
- 📢 рассылки: всем тренерам / всем клиентам / всем / клиентам тренера — любой
  контент, батчами через taskiq, отчёт о доставке админам;
- ❓ FAQ двух видов (для клиентов и для тренеров);
- 📥 CSV-выгрузки: тренеры, клиенты, тренировки, подписки и оплаты.

Заблокированные админом пользователи получают «Доступ ограничен».

**Ещё не реализовано:** онлайн-оплата занятий клиентами, AI-функции.

## Логи

Один формат для всех процессов (бот, воркер, планировщик, webhook):

```
2026-10-22 09:15:03 | ERROR   | bot | u=1020781796 cb=Ab12/booking_calendar:… | src.…:42 | [Mediator] CreateBookingRequest failed …
```

- **контекст** в каждой строке: кто и что нажал (`u=<tg id> cb=…`, `cmd=/start`,
  `text[N]` — сам текст не пишем, там телефоны и анкеты) или какая фоновая
  задача (`task=send_trainer_digests id=…`) — по нему ошибка связывается с
  пользователем и действием;
- **файлы** с ротацией (10 МБ × 5): `logs/bot.log`, `logs/worker.log`,
  `logs/scheduler.log`, `logs/webhook.log` и общий `logs/errors.log` (WARNING+
  всех сервисов) — **начинать поиск ошибки с него**; в docker это `./logs` на хосте;
- `APP_CONFIG__APP__LOG_LEVEL` (INFO; DEBUG — каждый вызов use case с временем),
  `APP_CONFIG__APP__LOG_DIR` (`logs`, пусто — только консоль);
- что пишется: строка на каждый апдейт с длительностью (WARNING, если > 3 с);
  каждый use case через `Mediator` — бизнес-отказы (INFO), медленные > 1 с
  (WARNING), падения с traceback и параметрами запроса (ERROR); каждая
  задача taskiq — старт, длительность, ошибка; недоставленные уведомления;
- общий обработчик ошибок бота: кнопки устаревших меню → «меню устарело,
  откройте /start», остальное → ERROR с traceback, пользователю — понятный
  ответ вместо тишины.

## Стек

- Python, aiogram + aiogram_dialog
- PostgreSQL + SQLAlchemy (async) + Alembic
- Redis — FSM-хранилище диалогов + брокер и schedule source для taskiq
- taskiq — фоновые задачи и планировщик (cron + отложенные задачи, см. ниже)
- matplotlib — PNG-графики статистики и дневника прогресса
- dishka — DI-контейнер

## Архитектура

Чистая архитектура, слои:

- **domain** — сущности (`Trainer`, `Client`, `Booking`, `CalendarSlot`, `SlotTemplate`,
  `TrainerInviteLink`, `TrainerSubscription` и др.), доменные сервисы (`CalendarService`),
  интерфейсы репозиториев, доменные исключения. Ничего не знает про БД/telegram/очереди.
- **application** — use case'ы поверх `Mediator`, оркестрируют domain через интерфейсы.
  Каждый use case — пара `Request` (dataclass) + `UseCase[Request, Result]`.
- **infrastructure** — SQLAlchemy-модели и реализации репозиториев, taskiq broker/worker/
  scheduler, DI-провайдеры (dishka), реализация `BookingScheduler`/`TaskQueue`.
- **presentation** — aiogram + aiogram_dialog: диалоги регистрации, бронирования, меню;
  роутер `/start` с обработкой deep-link токенов инвайт-ссылок.

## Как это работает — ключевые решения

**Календарь.** Тренер задаёт шаблон регулярных слотов (`SlotTemplate`, день недели +
время). Ежедневная taskiq-задача поддерживает буфер реальных `CalendarSlot` в БД на
~60 дней вперёд — ровно материализованные записи, а не "виртуальные" слоты, потому что:
на них держится блокировка тренером конкретных дат/слотов, и на них же держится
атомарность бронирования (защита от одновременной брони одного слота двумя клиентами).

**Регистрация.** Клиент попадает в бота только по персональной ссылке тренера
(`/start <token>`) — токен ищется в `TrainerInviteLink`, клиент привязывается к
конкретному `trainer_id`. Повторный вход по чужой ссылке не перепривязывает клиента —
он просто возвращается в меню своего тренера.

**Клиент без Telegram.** Это обычная строка `clients` с `tg_id = NULL` и
`source = MANUAL`: брони, постоянные записи, абонементы и статистика работают
без отдельной ветки логики. Все места, где бот пишет клиенту, проверяют
`client.has_telegram`. Персональная ссылка (`invite_token`) одноразовая;
автосклейки по телефону нет намеренно — легко склеить двух разных людей.

**Списание абонементов** — одно правило в `PackageChargeService`: его вызывают
автозавершение тренировки и отметка неявки/явки. Списывается абонемент, который
раньше сгорит; исправление статуса возвращает занятие.

**Фоновые задачи (taskiq):**

| задача | когда | что делает |
|---|---|---|
| `maintain_calendar_buffer` | 03:00 | слоты на ~60 дней вперёд (в отпуске — сразу закрытые) |
| `maintain_recurring_bookings` | 04:00 | тренировки постоянных клиентов на следующую неделю |
| `check_expiring_subscriptions` | каждый час | предупреждения и окончание подписки |
| `send_trainer_digests` | каждый час | утренняя/вечерняя сводка — у каждого тренера свой час |
| `send_attendance_requests` | каждые 30 мин | «придёте?» за ~сутки до тренировки |
| `send_training_reminder`, `mark_booking_completed`, `send_plan_next_training_reminder` | отложенные | напоминание, автозавершение (+ списание абонемента, запрос оценки, бонус за друга), «запланируйте следующую» |

**Партнёрская модель (задел на будущее).** `Trainer`, `TrainerSubscription`,
`TrainerInviteLink` спроектированы с расчётом на нескольких тренеров с первого дня,
хотя в MVP активен только один — это позволяет не переписывать модель данных, когда
появится реальное партнёрство.

## Локальный запуск

Требуется PostgreSQL и Redis (например, в Docker).

```bash
uv sync
uv run alembic upgrade head
uv run python -m src.main          # бот
uv run taskiq worker src.worker:broker       # воркер фоновых задач
uv run taskiq scheduler src.scheduler:scheduler  # планировщик (cron-генерация календаря)
uv run uvicorn src.presentation.web.app:create_app --port 8080 --factory  # webhook ЮKassa
```

Тесты и проверки:
```bash
uv run pytest                 # все слои; PostgreSQL поднимается встроенным pgserver
uv run ruff check src tests
uv run pre-commit install     # один раз: ruff + pytest перед каждым коммитом
```

Тесты разложены по слоям: `tests/domain`, `tests/application` (use case'ы на
фейках), `tests/infrastructure` (репозитории, миграции, уведомления — реальный
Postgres), `tests/integration` (use case'ы через DI-контейнер и БД),
`tests/presentation` (прокликивание диалогов через `aiogram_dialog.test_tools`).
Внешние системы (Telegram, taskiq, Redis) в тестах подменены фейками.

Бизнес-параметры (часовой пояс, тестовые режимы напоминаний, сроки предупреждений
о подписке и т.д.) задаются в `.env` — см. `APP_CONFIG__BUSINESS__*` в `.env.dist`.

Расписание: время, убранное тренером из шаблона, делает будущие слоты неактивными
(`is_active=false`) — их не видят клиенты, но существующие записи сохраняются.
`status=BLOCKED` — блокировка тренером («🚫 Блокировка дней/слотов» или отпуск).

Новые параметры второго этапа в `.env`: `APP_CONFIG__BUSINESS__MORNING_DIGEST_HOUR`
(час утренней сводки по умолчанию, 8), `APP_CONFIG__BUSINESS__INACTIVE_CLIENT_DAYS`
(через сколько дней клиент попадает в «😴 Давно не были», 21),
`APP_CONFIG__BUSINESS__TRAINER_REFERRAL_BONUS_DAYS` / `…_FRIEND_DAYS`
(бонусы реферальной программы тренеров, 30 / 7), `APP_CONFIG__APP__LOG_LEVEL` /
`LOG_DIR` (логи). Остальное
тренер настраивает сам в кабинете («📅 Запись», «🔔 Напоминания и сводки»).
FAQ для уже работающей базы дополняет миграция `c6e8a0b2d4f7`.
